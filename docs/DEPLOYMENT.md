# 在网页中部署 CloudInk

准备 GitHub 和 Cloudflare 账号即可。无需下载代码、使用命令行或准备域名。部署完成后，一个 Worker 和一个私有 R2 桶负责博客、后台、图片和数据存储。

## 1. 点击部署按钮

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/RS-Imagine/cloudink)

按页面提示登录、授权 GitHub 仓库连接，选择自己的 Cloudflare 账号。Cloudflare 自动复制项目、连接 Workers Builds、创建 Worker 和 R2 存储桶。资源名称可保留默认值；新站使用新桶，不要选择其他站点正在使用的数据桶。

首次使用 R2 时，可能需要按 Cloudflare 提示启用 R2 并添加计费信息。Worker 与 R2 均有免费额度，超额用量按平台收费。参见 [Workers 定价](https://developers.cloudflare.com/workers/platform/pricing/)和 [R2 定价](https://developers.cloudflare.com/r2/pricing/)。

## 2. 只填一个初始化口令

部署页面会要求 `SETUP_TOKEN`：填写一个自己保管的 16–128 字符私密口令。建议使用密码管理器生成。它作为 Cloudflare 加密 Secret 保存，不放进 GitHub，也不用添加到 Builds 环境变量。

保留默认构建命令 `npm run build`、部署命令 `npm run deploy` 和根目录 `/`。不需要额外填写邮箱、网址、存储访问密钥、构建 Token 或 Deploy Hook。

点击部署，等待 Cloudflare 显示成功。首次构建会安装 Rust 工具链、编译 WASM 和后台，耗时取决于构建环境。

## 3. 打开网站完成设置

打开 Cloudflare 显示的 Worker 地址，例如 `https://cloudink.reader.workers.dev`，在地址后加 **`/admin`** 进入后台。

首次设置向导分两步：

1. 输入初始化口令，设置管理员登录邮箱、12–128 字符的登录密码。
2. 填写博客名称、作者名称和可选的一句话介绍，点击“创建账号并上线”。

邮箱只用作登录账号，无需邮件服务。登录密码可以与初始化口令不同。账号创建后，初始化入口关闭，不接受公开注册；修改 Cloudflare 的初始化口令也不会重置现有账号。保留这一必需 Secret 供后续部署校验使用；它不会替代后台登录密码。

向导随后生成并发布首页。请保持页面打开并联网，等到“最新发布已上线”。如果首次发布失败，账号与设置已保存，重新登录后点击“发布博客首页”重试。

## 日常只使用后台

| 操作                            | 入口                            |
| ------------------------------- | ------------------------------- |
| 写文章、上传图片、导入 Markdown | 写作空间                        |
| 标题、作者、页脚、关于页面      | 网站设置 → 网站与外观           |
| 开启或关闭 Clarity 统计         | 网站与外观 → 访问统计，默认关闭 |
| 预览、复用和清理图片            | 侧栏 → 图片库                   |
| 修改登录邮箱、密码              | 网站设置 → 账号                 |
| 下载完整网站备份、恢复备份      | 网站设置 → 备份与恢复           |

保存草稿不会更新线上网站。修改网站信息后点击“发布网站信息”；编辑文章后点击“发布这篇”。所有页面上传完整后才切换版本，其他草稿不会跟着上线。

发布期间保持后台打开。断网或关闭页面后，原稿和上次成功版本仍保留；重新登录，取消未完成的发布，再重新发布。超过 30 分钟的任务会标记失败。

关于页面支持 Markdown，留空并发布后关闭该页面与导航入口。页脚为空使用默认文字。Clarity 项目 ID 为空时关闭统计；填写有效 ID 并发布后加载官方统计脚本，不支持粘贴任意脚本代码。

## 主题色与明暗模式

网站设置 → 网站与外观 → 主题与外观，直接点选墨绿、灰蓝、棕褐 Brown、靛蓝、紫藤或玫瑰色块。
点击“保存网站信息”后后台与文章预览立即使用新主题色；点击“发布网站信息”后，
所有已发布网页同步更新。只保存不会提前改变公开网站。

公开网站的明暗模式自动跟随读者的系统，不提供页脚设置或手动切换按钮；以前保存的明暗选择不会覆盖系统偏好。
视觉效果根据系统减少动态效果、减少透明度、对比度及设备能力自动选择，不需要读者设置。

后台外观仍可选择跟随系统、浅色或深色，以及“自动 / 简洁（不透明）”视觉效果。
这些选择只保存在当前浏览器并应用于后台，不会覆盖公开网站的系统明暗模式，也不改变作者发布的品牌配色。
已发布旧页面的控件由共享脚本与样式清理，刷新即可生效，无需为此重新发布文章。
无需在 Cloudflare 配置颜色变量，也不需要编辑仓库。

## 修改文章地址

编辑文章时展开“文章日期和地址”，点击“修改地址”，只填写地址末尾的名称（如 `my-first-post`）。
支持 1–100 个英文字母、数字、短横线或下划线。与已有文章、草稿或其他文章的旧链接冲突时会提示换一个地址。

草稿选择“修改草稿地址”后仍是草稿，不会自动发布。已发布文章选择“修改地址并发布”，将当前文章内容保存并发布到新地址，其他草稿不受影响。
旧链接自动以 301 跳转，重复改址时会直接跳转到最新地址；也支持改回自己的旧地址。地址变更沿用原有发布保护，未完成发布时旧版网站继续可用。
改址后的正文、图片引用与原稿保留，取消发布后仍可作为草稿继续写作；备份和下载原稿保留旧地址信息。普通 Markdown 导入作为新文章，不继承旧链接。

## 图片库与清理

默认启用节省空间的上传方式：大型静态图片在浏览器中压缩为宽度不超过 1920 像素的 WebP 主图，并按需生成较小版本；这一组文件的总字节数不会超过本次原始文件。不能有效压缩时保留原文件，不额外增加小尺寸版本。动图、小图、超大像素图片或浏览器不支持处理时也保留原样。点击文章大图显示保存的主图。\n\n如需要保存完整原文件，在图片库勾选“保留上传原始文件”。该选择保存在当前浏览器，也应用于编辑器的选择、粘贴和拖入上传。保留原文件时，响应式版本会额外占用存储。无需开通 Cloudflare Images、增加存储桶或设置变量。已有图片与链接不会被自动压缩或替换。

新上传图片自动处理。已有图片可在图片库展开“优化已有图片”，点击“扫描并优化”，确认下载量和新增存储上限后开始。原图和链接保留，不需要替换文章引用；请保持后台页面打开并联网，可选择完成当前图片后暂停。刷新后再次运行会跳过已完成项，失败项可重试；需要重新检查未转换的图片时勾选“重新检查之前跳过的图片”。

完成后点击“更新已发布文章的图片”，按现有线上内容重建网页，让旧文章使用压缩版本；不会发布草稿或未发布的网站设置。导入普通 Markdown 时，链接到已有优化图片的内容也会在发布时获得响应式属性。

侧栏的“图片库”展示名称、大小、上传日期和使用情况，按上传时间从新到旧加载。可批量上传、预览大图、复制完整链接；编辑器中的“从图片库选择”可把现有图片插入当前文章，无需再次上传。目录与引用信息一次读取，卡片在浏览器中分批显示；分页和筛选不会重复扫描存储桶。短时间内往返可复用结果，保存、上传、发布或手动刷新后重新读取。删除前仍会在服务端重新验证引用。

“删除”会在确认后永久移除存储桶里的原图及全部压缩版本。已发布文章、草稿、关于页面、网站设置和正在发布的内容都参与引用检查；存在引用时禁用删除，服务端在删除前再次检查。文章取消发布并删除草稿后，其中的图片不再受保护。检查无法完整完成时，仍可浏览与复用图片，但禁止删除。

图片库最多管理 2000 张图片。不会批量自动清空图片。过期发布产物按下述保留规则自动回收，原稿、图片与设置不参与回收。删除无法撤销，建议先下载网站备份。其他窗口中的未保存文字不属于已存储引用；保存时发现图片已删除，会保留编辑器文字并要求移除链接或重新上传。

## 一个存储桶的访问方式

`STORAGE` 是 Worker 的资源绑定，由部署流程配置。它允许程序访问自己的 R2，不需要用户创建 S3 访问密钥。

文章、账户、设置和图片在同一桶里按用途分类。**保持桶为私有，不开启 r2.dev 公共访问，也不将自定义域名直接绑定到 R2 桶。** 自定义域名应绑定 Worker。公开页面与图片由程序按规则提供，草稿和账户文件没有公开读取入口。

## 备份与恢复

“下载网站备份”生成 ZIP，包含待发布网站设置（如存在）、已发布原稿、草稿及上传图片。账号密码、登录会话和初始化口令不进入备份。备份含未发布的文字，请妥善保管。

恢复时选择该 ZIP。程序校验文件与图片，将文章恢复为草稿、设置恢复为待发布状态；不修改目标站点的账号和当前线上版本。相同原稿与图片可跳过，遇到同名不同内容时停止，不覆盖现有内容。恢复到新站时，先在新站完成初始化，再导入备份。

恢复不是一键恢复整个线上版本。检查设置并发布，再逐篇发布需要上线的文章。旧版本备份中的历史版本会被跳过。恢复被中断时已导入的草稿仍保存，重新选择备份可以继续，出现冲突则先处理现有内容。备份和恢复时避免在其他窗口修改文章或设置。

网页备份支持最多 8 MB 原稿，文字加图片最多 100 MB、最多 2000 个文字文件、2000 张原图及其压缩版本（至多 8000 个图片对象），单张图片最多 10 MB。备份已下载后不包含未完成的发布文件，也不包含可重新生成的 HTML、脚本和样式。更大的站点或需要精确保存线上快照时，通过 Cloudflare R2 做完整桶备份。

## 自定义域名与项目更新

- **域名可选**：在 Worker → Settings → Domains & Routes 添加 Custom Domain。域名需在同一 Cloudflare 账号中管理。地址按访问入口自动识别，上传图片使用相对路径，无需配置网站 URL。
- **自动部署**：向自己的 GitHub 仓库生产分支提交或合并代码，Cloudflare Builds 自动更新同一个 Worker。保持原桶绑定与 Secret，文章、账号及后台设置不会被代码更新覆盖。
- **上游更新**：Fork 可以使用 GitHub Sync fork；部署按钮创建的独立仓库副本需要自行合并上游变更。代码部署成功后，后台首页会提示是否有新版排版。点击“更新网站排版”重新生成全部已发布页面，完成后显示“网站排版已是最新”。此操作不会发布草稿或未发布的网站设置；发布期间保持后台打开。
- **平台设置**：域名绑定、Cloudflare 计费、GitHub 授权和构建连接仍在对应平台管理。网站后台管理博客设置，不需要 Cloudflare 账号管理 Token。

## 常见问题

**初始化口令忘了，尚未创建账号**：在 Worker → Variables and Secrets 修改 `SETUP_TOKEN` Secret，保存并部署，再回到 `/admin` 输入新口令。它必须为 16–128 字符，不是普通变量或 Builds 变量。

**创建账号时页面报错，重试提示已初始化**：使用刚才设置的邮箱和密码登录。账号创建与首页发布是两个阶段，正常登录会补齐被中断的空站初始化；可以再次发布首页。

**创建账号后忘记登录密码**：初始化口令不能绕过现有账号。仅 Cloudflare 账号所有者可以执行维护恢复：先备份 R2 桶，轮换 `SETUP_TOKEN` 并保存部署，然后仅删除桶内 `auth/account.json`，回到 `/admin` 重新设置账号。原有内容、设置和已发布版本保留，旧会话失效。不要删除桶或其他对象。若忘记邮箱，可由账号所有者在 R2 的这个文件中查看邮箱。

**构建失败**：检查 Cloudflare Builds 日志，确认根目录与默认命令。新模式只有一个 R2 绑定 `STORAGE`，运行时 Secret 为 `SETUP_TOKEN`。构建阶段不需要访问文章，也不需要 Secret 的明文。

**备份或恢复失败**：保持页面打开并联网，查看提示。原稿或图片冲突不会自动覆盖，先下载现有内容处理；如果超过网页备份限制，使用 R2 桶备份。不要为了恢复而清空正在使用的桶。

**更新排版时提示后台版本已更新**：先保存正在编辑的内容，再刷新后台并重试。旧标签页可能仍使用上一版 Rust/WASM；失败时草稿和线上版本均保留。不需要修改 Cloudflare 变量。

## 免费额度与自动维护

CloudInk 默认减少重复操作，不需要额外配置：

- **公开缓存**：使用现有 Cache API 缓存公开页面、RSS、站点地图和图片。公开版本指针最多缓存 30 秒，页面按版本隔离缓存 5 分钟，图片边缘缓存 1 小时。缓存命中时不必再次读取 R2；客户端条件请求仍支持 304。发布成功会清除当前数据中心的指针缓存，其他数据中心最多延迟约 30 秒看到新版。图库删除后，边缘缓存或浏览器中已有的图片副本可能继续可见一段时间。
- **增量发布**：首次发布或主动“更新网站排版”会生成完整站点，日常发布仅上传变化页面。相同页面在不同发布版本之间共用对象，CSS、脚本与默认图标直接使用 Worker 静态资源。当前线上版本仍通过条件写入一次切换，不会把半成品公开。
- **每日回收**：同一个 Worker 每天 UTC 03:17 执行有界清理；每次最多扫描 350 个对象，游标在后续天数继续。保留当前与最近两个成功发布版本，以及不足 24 小时的产物；有效发布进行中会暂停清理。仅删除不再引用的生成网页和旧发布快照，绝不删除原稿、上传图片、设置或账户。大批历史产物可能需要数日逐步回收。在后台“网站设置 → 运行信息”查看最近一次清理结果。
- **图库与保存**：图库目录和引用检查复用一次结果，在浏览器里分页；少量图片引用用较便宜的 HEAD 验证，短记保存引用索引。自动保存仍只写入发生变化的内容，不会定时重写空闲文章。
- **静态资源与统计**：编译的脚本、样式与字体由静态资源服务直接提供。未启用统计时不再发送无意义的统计脚本请求。

自动维护的日常开销约为每个站点每天两次 LIST、三次 PUT，删除本身免费；它用于避免旧产物无限累积。存储错误或发布忙碌时会停止本次清理并等待以后重试。无需添加数据库、存储桶、账号管理 Token 或环境变量。

R2 Standard 当前免费额度为每月 10 GB-month、100 万次 A 类操作、1000 万次 B 类操作，**不是超额自动停费上限**。容量按月平均占用计算；同账号其他桶也会占用额度。Cache API 命中仍算一次 Worker 请求，不能规避 Workers Free 每日请求额度。流量很大、反复上传或完整重建仍可能超额；请在 Cloudflare 查看 R2 使用量、Workers 套餐与账单通知。不要为降低访问费而启用没有该免费额度的 Infrequent Access 存储类别。

价格与限制以 [R2 官方价格](https://developers.cloudflare.com/r2/pricing/) 和 [Workers 官方价格](https://developers.cloudflare.com/workers/platform/pricing/) 为准。项目不能从博客后台准确读取整个 Cloudflare 账号的账单，也不会添加反而产生额外写入的逐请求计费计数器。

### 回退存储优化版本

本次新增的页面映射需要支持它的读取代码，不能在发布新格式后直接部署完全不认识映射的旧 Worker。需要完整退回旧版本时，先在当前代码的 `cloud-admin/src/publishing.ts` 将发布响应的 `incremental: true` 临时改为 `incremental: false`，部署后刷新后台并点击“更新网站排版”。这会使用保留的完整发布协议重新生成传统的版本目录；确认 `state/published.json` 中不再含 `pages` 映射后，再 revert 本次优化。先下载网站备份，不清空桶或原稿。只关闭缓存或自动维护时，可以保留映射读取与发布代码，无需转换已有内容。

### 图片引用索引升级

图片保护使用与 Markdown URL 解码一致的规范化规则，识别实体编码、转义、引用式图片和 HTML 图片。旧索引会从原稿重新核对，不直接信任旧的空引用结果。图库出现“更新引用索引”时可点击分批更新；每批最多处理 8 份原稿，保留原稿字节与其他元数据。中断后可再次运行，已更新项会跳过。引用无法完整检查时，图片继续受到删除保护。
