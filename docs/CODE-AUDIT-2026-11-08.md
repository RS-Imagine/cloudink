## 排版更新的工作方式

代码部署会更新 Worker、公开脚本与 CSS；R2 中已发布的 HTML 来自上次发布快照。因此，仅部署代码不会自动换掉旧 HTML 的结构。已有的 Rust 模板指纹和服务端 `templateStatus` 能识别这种情况，问题在于 UI 改动隐藏了操作入口。

修复后，后台各视图顶部均可找到“更新网站排版”。提示有新版排版时点击一次，浏览器用当前 Rust/WASM 重建已发布快照，上传完整内容后原子切换线上指针。该操作不发布其他文章、短记草稿或待发布的网站设置。失败时保留原稿和上次线上版本；旧渲染引擎会提示刷新后台。首次首页生成后，按钮立即显示正确的新状态。

没有增加静默自动发布、存储迁移或新 Cloudflare 资源。部署这次修复后，仍需按提示更新一次已发布页面。

## 资源体积核对

将 ZIP 备份工具改为进入设置时按需加载，主入口从约 36.5 KiB gzip 降至约 28.6 KiB，回到原有 29 KiB 护栏内。备份仍走同一任务接口，完整导出、恢复和账户流程已单独回归。

CSS 仍超出原有体积护栏，本次保留阈值，并在审计结束后返回失败；功能通过与资源达标分别记录，避免把其中一项当成另一项。按同一构建算法比较 `d3656c4` 与本次源文件，结果如下（gzip 字节）：

| 资源                       |   基线 |   本次 | 原预算 |
| -------------------------- | -----: | -----: | -----: |
| 公开 CSS                   | 14,614 | 14,458 | 13,312 |
| 后台 CSS（包含图片库样式） | 17,909 | 17,290 | 15,360 |

备份懒加载前后的入口体积不等同于远端基线对比；该数字仅用于说明同一轮修复中的打包拆分。最终资源数据以 `build-work/ui-audit/report.json` 为准。旧发布 HTML 仍依赖部分兼容选择器，因此没有仅为压低体积而直接删去这些规则。

## 前后台接口核对

| 接口                                           | 核对结论                                                                                                                      |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/posts?limit&q&filter&cursor`         | 文章卡片使用 `posts`，概览使用 `counts`；排版入口使用 `publicInitialized` 和 `templateStatus`，分页查询也纳入浏览器拦截回归。 |
| `GET /api/shorts?limit&cursor`                 | 总数使用 `total`；列表内容是摘要，编辑前必须读取单篇接口。                                                                    |
| `GET/PUT /api/shorts/:slug`                    | 编辑加载完整 `body_markdown`，保存携带对应 `etag`；过期读取不能修改新编辑对象。                                               |
| `PUT /api/posts/:slug`                         | 文章保存仍携带草稿和 ETag；导航继续等待 flush，不绕过并发冲突。                                                               |
| `POST /api/publish` 及 plan/file/commit/cancel | 复用现有增量发布、模板版本校验、上传收据与线上指针协议；rebuild 只消费已发布快照。                                            |
| `GET/PUT /api/settings`                        | 六套主题值和插画、图标字段与服务端模型保持一致；保存和公开发布分离。                                                          |
| `GET /api/export`                              | 服务端的 410 兼容响应保留，当前界面已无调用。                                                                                 |
| `/api/backup/jobs`                             | 继续使用既有分批导出与恢复流程；入口在网站设置中。                                                                            |
| `/site-icon/:name`、`/images/:key`             | 使用公开路由地址，不把私有 R2 键当作网页相对路径；原有鉴权、引用检查和路径白名单保持。                                        |

## 后台设计交付

桌面为深棕侧栏、暖白工作区、欢迎区、四个真实内容指标和独立快捷操作；手机为紧凑顶栏、两列指标、按需展开的五项导航菜单。编辑、图片、短记和设置沿用同一表面与间距系统。深色和作者配色由原有主题控制器管理；导航侧栏使用独立的深色表面维持文字对比。

## 按最新要求收敛

- 手机只保留紧凑顶栏，导航按需进入现有原生面板；选择目的地、Esc 或关闭后归位，没有新增弹层框架或第二套导航数据。
- 移除为悬浮底栏准备的键盘隐藏规则和 112px 底部预留；保留安全区与编辑器键盘几何处理。
- 删除新增回归中重复的尺寸、配色和截图矩阵，合并到既有编辑/初始化流程；移除失效的底栏显隐断言与临时诊断代码，复用一个导航操作辅助函数。改址测试直接校验下载原稿中的别名，不再重复请求旧的整站备份接口。
- 将动效回归收敛到真实鼠标/键盘操作、对话框焦点与 API 回退，去掉绑定动画帧数和缩放实现的断言。图片预览的动画能力检测改为判断函数可调用，保留缺失 API 时的正常预览。
- 按功能重绘文档新建、短记、图片、设置、格式工具、目录、回顶及分享 SVG；有文字的普通按钮继续保留文字，避免堆叠装饰图标。专注写作按钮同步显示进入/退出状态，并修复桌面专注模式仍保留侧栏列宽的问题。
