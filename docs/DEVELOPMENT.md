# 开发 CloudInk

CloudInk 使用单个 Cloudflare Worker 和一个私有 R2 桶。Rust/WASM 负责 Markdown 与页面生成，原生 JavaScript/CSS 负责浏览器交互；不引入额外数据库或前端框架。部署步骤见 [部署教程](DEPLOYMENT.md)。

## 目录与构建

- `crates/blog-core`：Markdown、数学公式、配置校验与页面模板。
- `crates/blog-wasm`：将同一渲染核心提供给浏览器 Worker。
- `crates/sitegen`：原生静态构建入口。
- `cloud-web/src`：唯一 Worker 入口、公开页面、图片路由与响应增强。
- `cloud-admin/src`：认证、草稿、短记、设置、图片、备份与发布 API。
- `cloud-admin/ui`：后台界面、预览线程与图片压缩线程。
- `assets`：正式前后台共用的主题、动效、图标与默认插画。
- `scripts`：构建、类型生成与正式界面回归工具。
- `cloud-web/test`、`crates/blog-core/tests`：功能与渲染测试。

需要 Node.js 24、Rust 1.98.1。Rust 版本由 `rust-toolchain.toml` 固定，依赖版本使用锁文件。

```bash
npm ci
npm run build
npm run check
npx wrangler deploy --dry-run --outdir cloud-web/dist
```

`build` 准备 Rust/WASM 和后台资源，不读取个人网站配置与文章。根目录 `wrangler.jsonc` 是唯一部署配置；`cloud-admin` 不单独部署。绑定类型从该配置与 `.dev.vars.example` 生成。

构建产物、个人文章、凭据、真实部署配置和截图不提交。仓库不保存设计原型、历史审阅包和阶段性实施计划。保留必要的开发、部署与许可说明。

## 云端检查

PR 自动运行构建、类型检查、Node/Rust 测试和 Chromium 核心流程。合并到 master 后不重复运行；直接推送 master 也不触发 Project checks，代码应通过 PR 验证。

在 GitHub **Actions → Project checks → Run workflow** 可手动执行基础检查；勾选 `visual_audit` 才运行正式页面的三浏览器回归。Cloudflare Workers Builds 独立负责部署。

可用命令：

```bash
npm run format:check
npm run format:ui:check
npm test
cargo test --workspace --locked
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked
npm run test:web:browser
npm run test:ui:audit
```

测试使用临时 Miniflare 存储与示例内容，不连接生产 R2。浏览器检查需要在 `cloud-admin` 下安装对应 Playwright 浏览器。完整审查输出到被忽略的 `build-work/ui-audit/`，包含正式页面截图、资源预算和实验测量；不包含历史设计原型。真实手机输入法、辅助技术与能耗仍需真机验证。

基础回归保护认证、草稿并发、图片引用、发布原子性、备份恢复及路由。视觉检查按需运行，不用截图数量代替功能验证，也不通过提高预算掩盖资源增长。

## R2 数据与权限

- `auth/account.json`、`auth/sessions/`：账号与会话，仅后台访问。
- `drafts/`：文章草稿；`shorts/`：短记草稿。
- `draft-site.json`：待发布网站设置。
- `releases/`：文章、短记和网站设置的发布快照。
- `state/`：线上版本指针与进行中的发布状态。
- `public/<版本>/`：完整生成的公开页面。
- `uploads/`：图片、压缩版本及网站图标。

桶必须私有；路径前缀不是权限边界。公开 Worker 只提供当前版本的固定页面和经过校验的图片路径，不代理任意 R2 对象。代码更新不得清空桶、重置账号或覆盖用户配置。

账号初始化使用 R2 条件写入保证唯一性。密码使用加盐 PBKDF2；会话 Cookie 使用 HttpOnly、Secure、SameSite，写接口检查来源与 CSRF。文章与设置通过 ETag 防止并发覆盖；涉及图片引用的内容变更通过 `storage-mutations.ts` 的租约协调。

## 发布、地址与模板更新

草稿保存不等于公开发布。浏览器用 Rust/WASM 渲染发布快照，上传完整文件后通过条件写入切换线上指针。取消与提交并发不得恢复已取消的发布。失败保留原稿和上次成功版本。

`blog-core/build.rs` 对模板输入生成 BLAKE3 指纹，原生/WASM 输出同一 `template_version`。待发布版本绑定开始时的模板版本；后台发现旧引擎时停止上传并提示刷新。

部署 Worker 后，已发布 HTML 不会自动重新生成。后台“更新网站排版”复用 rebuild，只重建已发布快照，不发布其他草稿或待发布设置。测试不得自动重建生产内容。

排版按钮和 `template-status` 使用同一组节点：宽屏文章管理显示在右侧，窄屏和其他栏目移到工作区顶部，保持可见并共享发布状态。发布控制共用忙碌状态，首次生成首页后按钮立即切换为“更新网站排版”。原有模板指纹、旧引擎拒绝、失败保留线上版本与增量上传协议保持一致。

文章改址通过独立表单完成。草稿改址使用 ETag、目标槽位检查和可恢复的搬移过程；已发布文章沿用发布流程。旧地址存入 `FrontMatter.aliases`，线上返回同源 301，保留查询参数，不生成跳转链；取消发布后不暴露私有草稿地址。

回滚代码使用对应提交的 revert，再部署 Worker。需要恢复旧模板 HTML 时，在确认模板兼容后重新生成已发布页面；不能通过清空 R2 回滚。

## Markdown、短记与预览

Markdown 公式预处理使用现有 pulldown-cmark 的源位置识别代码范围，保留原有 `$…$` / `$$…$$` 写法（包括 `$ x $`），再交给 KaTeX 渲染。代码示例中的美元符号保持原文；普通货币文本可用 `\$` 转义。搜索索引保留代码原文，不收录公式占位标记。

普通 Markdown 导入由 `blog-core/src/import.rs` 处理，无需头信息；也支持可选的 `+++` TOML。缺省标题取开头普通一级标题或文件名，缺省日期取浏览器本地日期。复杂标题、代码、公式与正文保持原意，显式错误元数据返回错误。

导入每次新建草稿和地址，不能用文件覆盖已有文章。每批最多 100 份 UTF-8 文件，单份最多 1 MB。导入前保存当前编辑内容；取消只停止后续文件，不删除已保存项。持久化原稿、发布快照和备份继续使用严格 TOML 格式。

短记使用独立 `/api/shorts` 接口与 `markdown_shorts` 发布快照字段，在 `/shorts/` 按时间倒序展示。日期使用 `YYYY-MM-DD HH:MM`。

短记正常保存、网页分批恢复和旧版兼容恢复共用元数据生成逻辑，保持日期、300 字符摘要、原稿摘要哈希与图片引用一致。列表按元数据分页，不为修补摘要逐条读取原稿。旧版本已恢复且缺少摘要的短记，可打开后正常保存一次补齐；重复恢复相同内容仍跳过原稿写入。

后台文章预览与公开站点使用同一 Rust 模板和共享样式，预览在 Web Worker 中生成，在禁止脚本的 iframe 中展示。异步回调必须核对当前编辑对象，不能覆盖用户后续输入。

## 图片与备份

上传线程为符合条件的 JPEG/PNG/静态 WebP 生成 640/1280/1920px WebP，保留原图、不放大。小图、动画、不支持的格式、超大像素和超时回退原图。服务器重新校验类型、尺寸、比例和大小后写入 R2。

正文发布时补齐托管图片的尺寸、srcset 与 sizes，保留明确指定的属性；首张正文图优先加载，其余懒加载。外部图片不下载或转换。图片库使用缩略图，刷新保留已有卡片，失败可重试。

文章与短记在保存时检查托管图片是否存在；短记发布时再次检查，兼容修复前保存的旧草稿。校验与删除沿用同一内容修改租约，失效链接不会写入，外部图片和代码示例仍可保存。

公开图片允许同源 Referer 或无 Referer 的 GET/HEAD 请求，以支持分享抓图、隐私设置和直接访问；明确跨站或无效的 Referer 返回不可缓存的 403。允许的图片响应保留 `Vary: Referer` 和 ETag。此规则用于减少盗链，不作为私有内容的访问授权；路径白名单仍排除账号、草稿等对象。

图片删除先检查线上版本、进行中的发布、文章草稿、短记及设置引用；异常或超限时不判定为未引用。原图与压缩版本按组保护与删除。已有图片优化支持暂停、续跑及失败重试，更新已发布页面需单独执行 rebuild。

网站图标仅接受不超过 256 KiB 的 SVG/ICO。SVG 重写为静态白名单内容，ICO 校验目录、尺寸与像素数据；图标采用内容地址，保存应用后台，发布应用前台。

备份 ZIP 包含设置、原稿、图片与 SHA-256 校验，不导入账号或线上指针。恢复先校验清单，文章与短记均优先选择备份草稿而非旧发布稿，内容仍作为草稿导入。已删除原稿可通过删除标记的 ETag 条件写入恢复；正常原稿的不同内容、已改址原稿及并发变化仍受冲突保护，不自动发布或修改线上指针；中断可保留已恢复部分并重试。备份上限为 2000 张原图及对应至多 8000 个图片对象，8 MB 原稿、100 MB 文字和图片总量。

备份导出与后台列表共用活动原稿扫描规则：文章、短记目录分别最多扫描 10000 个对象、保留最多 2000 份活动原稿。删除/改址标记只占扫描预算，不占有效备份条目；发布稿与草稿合并后仍受 2000 份文字、8 MB 文字、图片及总量上限约束。导出不清理或改写删除标记。

## 前台资源与交互

`assets/design-tokens.css` 是前后台共享的颜色、字体、间距与圆角来源。作者配色存入网站设置，保存影响后台和预览，发布影响公开网站。前台默认跟随系统，可单独切换；读者偏好与后台偏好使用不同的本机存储键。阅读字体通过可选 `readingFont` 配置：`serif` 为默认原字体、`sans` 为 V4 无衬线；缺省和旧备份按衬线处理。字体只影响文章标题和正文，导航与后台维持无衬线。保存仍不等于发布，预览使用已保存的字体设置。

后台 `cloud-admin/ui/prism.css` 实现 V4 的浅色侧栏、文章管理列表和编辑布局，颜色继续使用共享 Token。默认进入文章管理，不再重复展示统计卡和文章切换列表。手机保留一套四项底部导航；进入编辑器时隐藏底栏，文章日期和地址通过 `editor-info-dialog` 按需查看，使用原输入节点，避免丢失选择或保存状态。保存状态在标题下持续可见；发布前确认，仍沿用原保存队列、ETag 和发布协议。

公开页面保留左栏、`#reader-center` 和 `#reader-context`；Swup 只替换两列内的内容节点。直接访问仍是完整服务端页面，缺少新容器的旧页面回退普通导航。`reader-tools.css` 保留代码、图片、搜索等阅读工具与旧快照的基本可读性。正文全文搜索继续匹配公开索引的 `title`、`description` 和 `body`。相关文章复用同一公开索引，不改变单篇增量发布的范围；字体失败使用系统回退，不阻止阅读。

`ui-audit-regressions.browser.mjs` 已接入 Chromium 常规流程和三浏览器审计，专门覆盖短记总数、完整原稿与异步保存的身份保护，复用常规初始化流程；布局、排版入口、主题和导航由既有对应模块负责，避免重复矩阵。

短记草稿仍需手动保存。新建、切换编辑对象、取消和退出前，未保存的正文或日期修改需明确确认放弃；普通栏目切换保留编辑内容，刷新或离开页面使用浏览器原生提示。保存成功只更新对应请求的已保存基线，保存期间继续输入或保存失败仍视为未保存；退出成功后清除当前编辑缓冲。

默认写作插画、登录页枝叶资源、项目图标和共享 CSS 都是正式运行资源，不能按文件名中的设计词汇删除。自定义首页插画及关闭选项由网站设置管理。

动效由 `motion.js`、`mobile.js` 提供，支持减少动态效果、取消、键盘替代、焦点恢复与移动面板。业务保存不得依赖动画完成回调。

代码高亮仅在需要时加载；KaTeX 样式与字体由本站提供。Swup 在内容切换前准备目标页面及必要资源，成功后同步标题、canonical、Open Graph、Twitter 与 JSON-LD；失败保留当前内容，过期响应不得替换新页面。

搜索引擎元信息根据请求域名生成，支持 workers.dev 和自定义域名。站点地图只列出公开页面，404 标记 noindex，后台和草稿不进入收录。ETag 包含渲染版本、域名与路径。

## 修改原则

- 保持 Rust/WASM 与原生构建的输出一致。
- 不在 UI 整理中修改认证、存储格式、发布指针或并发保护。
- 清理文件前检查构建入口、运行时路径、测试引用和文档链接。
- 功能变更补充对应行为验证；可逆的文档或样式整理避免重复测试。
- 格式化仅限需要修改的文件，审查 diff，避免整目录重排。

## 按改动范围执行 CI

PR 先根据基线与提交的文件差异选择检查。纯文档改动只完成范围检查；代码改动执行格式、构建、类型与存储/认证/发布测试。Rust 源码、Cargo 或 CI 变动才运行 Rust 测试和 Clippy；影响界面、公开响应或构建配置时才运行 Chromium。完整三浏览器视觉审计继续仅手动触发，合并后不再重复运行 PR 检查。

新增的存储优化回归测试使用临时 Miniflare R2 与测试内的时间适配器，检查页面复用、缓存边界及生成产物保留规则，不访问生产桶。每日维护通常执行五个 LIST（生成物三个、引用分片一个、会话一个），删除只限严格识别的发布键；维护与内容变更共用原有条件写入锁。缓存仅用于公开响应，不缓存账户或后台 API。

图片功能冒烟默认只验证两个视口的响应式加载、字节数、延迟加载、预览和备份保护。需要重新测量完整性能对比时，构建后显式运行 `CLOUDINK_PERF_AUDIT=1 node cloud-web/test/images.browser.mjs`；这才执行 3 次交错样本和网络/CPU 限速，不在每次 PR 上重复测速。

手动启用完整视觉审计时只运行对应的审计任务，避免再启动一次相同的功能验证构建。PR 检查的文件范围取自实际合并快照与其基线，避免把上游新增、且本 PR 未改动的文件误算成自己的变更。

## 后端读取与写入预算

旧的 `GET /api/export` 返回 410，后台备份统一使用现有分批任务。账户鉴权后才返回升级提示，不读取全量原稿。

文章和短记保存先检查地址、图片存在性与 ETag，再比较服务端生成的完整原稿摘要 `source_digest`。摘要与编辑摘要独立；旧原稿第一次保存补齐摘要和引用元数据。相同原稿、相同设置和相同图标复用原对象，不发送内容 PUT；内容租约的取得与释放仍产生写入。不同 ETag 继续返回 409，不因内容相同绕过冲突保护。

媒体使用独立的 `media-v1` 边缘缓存命名空间，响应安全规则变化时须更新该版本。普通图片与自定义图标均缓存一小时；无关后台部署不再使媒体缓存整体失效。公开页面按内容映射、域名路径、响应处理版本与统计配置隔离，未变化页面可跨发布复用。没有增加随机路径负缓存。

文章列表与短记列表仅在当前后台标签页的内存中短暂复用十秒，并合并相同在途读取。修改开始和成功时、认证失效、窗口重新获得焦点以及其他标签页发送修改通知时清空；不使用浏览器持久存储、公开 Cache API 或 R2 保存私有列表。分页请求在服务器端仍检查当前快照，目录仍有界扫描；此方案避免每次自动保存额外维护持久目录索引。列表有效原稿上限 2000，扫描上限 10000，删除及改址标记保留用于拒绝旧编辑器写回。

发布私有摘要新增可选短记摘要与带版本的图片引用摘要，仍存入已有 `releases/{id}.posts.json`，没有增加每次发布的对象数量。未变化内容复用摘要；图库优先读摘要，旧版本缺字段时只读回退到原发布快照，损坏摘要禁止删图。图库客户端仍复用已有目录，执行删除时在内容租约内重新核对线上、待发布、备份、原稿和设置，不信任界面旧结果。发布快照继续沿用完整 JSON 格式与大小限制，本次仅避免深复制，不宣称已经实现独立内容对象或完全免除整站传输。

每个请求的存储计数只保存在内存，失败、超过 150 次存储调用或约 1% 样本输出结构化日志，包括关联 ID、最近存储阶段、调用数量、扫描对象数、状态和经过时间。响应带 `X-Request-ID`，日志不记录正文、Cookie、密码或完整对象键。经过时间不等于 CPU 时间；平台日志使用低比例采样，traces 默认关闭；实际套餐 CPU 仍须查看 Cloudflare 平台指标。没有逐请求 R2 计费计数器。

每日维护另扫描最多 32 个会话，优先使用登录时已有会话 PUT 附带的到期元数据；旧会话最多读取 32 个小对象。只删除可确认已过期的、路径格式正确的会话，未知格式保留。会话扫描游标写入已有维护状态，不新增每日状态对象；删除标记不会自动清除。
