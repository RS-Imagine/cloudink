# 棕褐书刊 UI 全界面补全计划

## 目标与边界

本计划补齐 EDITORIAL-SYSTEM.md 中未覆盖的后台整体设计。此前 PR #29–#33 完成公开网站书刊样式与插画配置，不代表全部后台已经重设计。

以作者已确认的棕褐书刊概念为视觉依据，前后台共享 design-tokens.css 的语义颜色与字体。保留所有可选配色，禁止强制覆盖作者选择。标题使用阅读字体，控件使用系统 UI 字体，正文和代码维持原有排版语义。

沿用 Rust blog-core / WASM、原生 JavaScript/CSS、Swup、单 Worker 和私有 R2。后台样式与静态 DOM 调整保留原始 ID、表单、导航、选区、认证、草稿并发、发布和引用保护。不增加框架、环境变量或服务。

## 独立交付顺序

1. 后台外壳与身份入口：启动、登录、初始化两步、桌面侧栏、平板图标栏、手机导航、工作台、文章列表、筛选、搜索与文章选择。独立 PR。
2. 工作流与浮层：写作/分栏/预览、文章属性、保存/发布/删除、图片库与优化、外观/账号/备份/运行信息设置、导入/确认/图片/手机面板。独立 PR。
3. 全界面验收：公开网站与后台的明暗主题、1440/390/360px 截图；320px、平板、键盘、减少动态效果、失败恢复、长文本、完整发布与三浏览器回归；使用与回滚说明。独立 PR。

前两项通过适用检查后合并，最后一项完成全界面截图与功能审查。每个 PR 可独立 revert，无数据迁移。仅完成一个阶段时明确标示已完成范围，不以整轮完成表述。

## 设计矩阵

| 区域 | 设计要求 | 验证 |
| --- | --- | --- |
| 启动与失败 | 稳定纸面卡片、状态说明、可重试 | 慢请求、错误、重试 |
| 登录、初始化 | 书封式介绍、独立表单、手机纵向布局 | 两步切换、校验、焦点、明暗 |
| 全局导航 | 细线边界、当前页强调、清晰层级 | 桌面/平板/手机、Esc、触控 |
| 工作台、文章 | 无装饰大卡片、衬线标题、文章行与下划线筛选 | 空/筛选无结果、长标题、状态 |
| 编辑器 | 纸面文档、克制工具栏、清楚的属性和预览边界 | 自动保存、失败、选区、切换、发布 |
| 图片库 | 联系印样式网格、原图保真、明确引用和操作状态 | 上传、筛选、预览、保护、错误 |
| 图片优化 | 可展开维护区、进度、暂停和结果 | 原优化与重发流程 |
| 设置 | 编号章节、目录、清晰表单与就近反馈 | 外观/账号/备份/运行信息 |
| 弹窗与面板 | 小圆角纸面浮层、统一标题与操作、手机安全区 | Esc、取消、焦点返回、手势替代 |
| 公开首页、文章、关于、404 | 已有书刊设计保持一致 | 有/无插画、正文、目录、搜索 |
| 搜索、分享、图片、移动目录 | 保留原语义与共享动效 | 键盘、缩放、返回与减少动态 |

## 验收与诚实边界

测试仅在 GitHub Actions 的隔离临时存储进行，不做本地测试、不新建测试 Worker、不测试或修改生产 R2。云端构建、格式、类型、Rust fmt/Clippy/测试、Node 测试、dry-run 与三浏览器按现有质量门槛运行。保留既有资源预算。

截图必须包含真正的后台页面，不能用独立前台原型替代。云端浏览器与模拟触屏不等同于真实 iOS/Android。专业设计案例在线研究与真机确认仍有局限，不将其宣称为完成。

## 发布

后台随程序部署更新，重新打开后台应直接获得新界面。公开页面按现有机制保存并发布网站信息后重建；不自动发布草稿、不为测试触碰作者生产内容。若后台未出现新版，应检查 Worker 的 Git 提交与实际静态资源版本，而非笼统要求发布文章。
