# CloudInk 棕褐色阅读与写作界面

## 本轮范围与设计依据

用户已确认保留棕褐色和现有字体，允许整体重新设计。本轮替换上一轮以植物插画和细线分栏为主的布局约束，直接改动正式 Rust 模板、共享设计变量与前后台样式。历史概念原型用于记录，不代表这轮的验收目标。

设计工作采用 [ai-design-skills](https://github.com/elayadesign/ai-design-skills) 的页面层级、间距、组件、动效与响应式方法，以及其要求的现有项目审计流程。品牌字体按用户要求保留。营销页面中的定价、推荐语和促销模块不适用于个人博客，不引入。

读者的主要任务是发现文章并安静阅读；作者的主要任务是继续写作、发布和管理内容。装饰不能成为完成这些任务的前提。

## 问题与对应改变

| 原有问题 | 本轮处理 |
| --- | --- |
| 首页依赖插画和丰富的演示内容才有构图 | 无插画布局独立成立；单篇文章也有明确的标题与阅读入口 |
| 文章缩略图过小，主次不清 | 第一篇采用大图文布局，其余文章保留紧凑列表；响应式 sizes 与真实展示宽度对应 |
| 手机导航像临时弹出的小框 | 原生 details 增强为全高度不透明导航，保留无脚本打开能力、Esc、点击空白关闭与焦点离开关闭 |
| 后台重复细线、分组缺少层级 | 紧凑欢迎区、文章表面、分段筛选、统一工具栏与表单分组 |
| 手机编辑器标题被基础输入样式覆盖 | 提高文档标题选择器的准确性，并验证计算字号至少 30px |
| 阅读页与后台预览字体和版心不一致 | 继续使用同一 Rust 渲染器、字体资源和阅读样式 |
| 大面积玻璃可能增加滚动成本 | 仅桌面小面积导航与浮层增强；手机全屏导航始终不透明 |

## 视觉规范

### 颜色与字体

- 保留 Brown 调色板及六种可选品牌配色；站点设置继续控制前台与后台。
- 共享 `assets/design-tokens.css`，不建立平行主题系统。
- Noto Serif SC 用于标题与阅读，系统无衬线用于控件，等宽字体用于源码。
- 背景和组件使用纯色表面；仅首页标题允许轻微文字渐变，高对比模式回退为系统文字色。
- 深色背景采用近黑中性色，保持正文与次级文字对比度。

### 尺度与结构

- 字号采用 12、14、16、18、20、24、30、36、48、60、72 的层级。
- 常规间距采用 4、8、12、16、24、32、40、48、64、80；细边框与图标笔画不受布局间距限制。
- 导航圆角 24px，主要表面 24px，控件 12px；手机窄导航 20px。
- 桌面首页最大外框 1200px；文章正文 680px，目录 192px，间隔 64px。
- 首页第一篇突出，后续列表克制；没有图片时不创建图片占位。
- 插画仍可在后台更换或关闭，关闭后不留下空栏。
- 后台桌面基础设置可双列，手机恢复单列；图片库手机采用两列，极窄屏一列。

### 动效与状态

- 使用共享运动控制器和真实弹簧按压反馈，保留取消、速度与减少动态效果支持。
- 普通状态变化 200–300ms，位置变化约 500ms，下方文章首次进入视口 650ms。
- 页面初始可见内容不为入场动画隐藏；离开 Swup 页面时清理观察器与动画。
- 全屏菜单只有链接的位移与透明度动画，不持续渲染背景。
- Loading、空状态、禁用、错误、保存与发布反馈继续使用现有业务状态。
- 不为改版引入大型框架、动画库或持续渲染循环。

## 真实页面验证

所有截图来自 GitHub Actions 内的临时 Miniflare 与 R2，经过正式 Rust/WASM 渲染、上传优化及发布流程。无生产账户内容、域名配置或 R2 数据参与测试，不创建 Cloudflare 测试 Worker。

覆盖以下场景：

1. 有插画、三篇文章和真实照片的首页与阅读页。
2. 无插画、中文介绍、仅一篇无图文章的首页。
3. 现有空文章列表、长标题、长链接、禁用关于页及无脚本导航检查。
4. 登录、初始化、工作台、文章列表、编辑、预览、图片库、设置、确认弹窗。
5. 1440、768、390、360 和必要的 320px 布局；明暗主题；减少动态效果；Chromium、Firefox、WebKit。

视觉审阅照片来自 [Autumn Lake Landscape](https://commons.wikimedia.org/wiki/File:Autumn_Lake_Landscape.jpg)，作者 Holly's Coastal View，CC0-1.0。下载与校验只用于测试，来源和摘要保存在审阅包的 `photo-source.json`，不会成为用户站点的默认内容。

自动检查是功能、可访问性与性能护栏，不能替代人工对真实截图的视觉判断。以当前上线版本作为后台前后对照，历史原型明确标注为历史参考。

## 架构与资源约束

保留单 Worker、单私有 R2、Rust/WASM、原生 JS/CSS 和 Swup；不改变存储格式、文章地址、认证、CSRF、自动保存、并发保护和图片引用规则。资源预算、18% 视口模糊面积上限与核心流程断言继续有效。仅 CSS 和浏览器交互使用必要的原生技术。

检查在云端执行：格式、构建、类型、Worker dry-run、Node 与 Rust 测试、Rustfmt/Clippy，以及三浏览器 UI 检查。未通过时修复实现，不能把质量门槛改成放行条件。

## 交付与回滚

本轮先提交可审阅 PR、截图与测量结果，不自动部署，待真实页面视觉确认。没有修改生产数据。合并后若模板结构有变化，应通过后台现有的更新网站排版操作生成新版公开 HTML。

回滚采用 revert 本轮提交并按现有流程重新生成网站排版，不要求恢复或清空文章、图片和账户数据。
