# CloudInk 2.0 · UI 升级与验收

本次升级统一公开博客、后台和文章预览的视觉系统，保持单 Worker、单私有 R2、
Rust/WASM、原生 JavaScript/CSS 与 Swup 架构。没有新增服务、运行时依赖、必填配置或存储迁移。

状态：PR-00 至 PR-08 已分阶段合并；PR-09 为最终回归与发布候选。
自动化检查与实验数据见对应 PR 的 CI 和 `ui-design-review` 附件。
真实设备与辅助技术验收仍需按下列清单完成，不能将模拟结果写成实机结论。
本阶段没有部署生产资源或重新发布用户内容。

## 用户能看到的变化

- 前后台共享墨绿 / 中性灰蓝、浅色 / 深色 / 跟随系统、圆角、排版和焦点状态。
- 首页以介绍区和文章卡片呈现内容，阅读页有清晰的标题、正文、目录、搜索和图片预览。
- 后台采用工作台与统一导航，编辑器提供写作 / 分栏 / 预览，图片库与设置采用相同组件语言。
- 按压与面板使用可中断的真实弹簧，支持减少动态效果；正文与编辑器不会被动画替换。
- 手机面板支持拖动把手、停靠、关闭，也能点击、使用方向键或 Esc；键盘输入时保留可用工作区。
- 小范围导航和菜单支持轻量磨砂。效果可在当前浏览器关闭，系统和低资源策略提供不透明降级。

**作者配色**：后台“网站与外观”选择主题色，保存影响后台与预览，发布后应用到公开网站。  
**读者偏好**：明暗模式与“自动 / 简洁（不透明）”只影响当前浏览器，不改变作者的网站设置。

## 更新现有部署

1. 在 GitHub 同步或合并所需上游代码，等待 Cloudflare Workers Builds 成功。
2. 打开 `/admin`，检查登录、主题、编辑器与图片库。无需重新初始化账号或存储桶。
3. 在后台发布一次网站信息，使所有已发布文章重新生成新版 HTML/CSS。保持后台打开并联网直至完成。
4. 检查公开首页、文章、搜索与手机导航。发布失败时保留上次成功版本，可按已有流程重试。

单纯保存草稿不会更新公开页面。仅部署代码也不会重新生成桶中的旧 HTML；
公开模板升级需要上述重新发布步骤。新用户仍按 README 的三步部署流程操作。

## 最终收尾范围

- 修复模拟的“键盘已缩小视口 → 双指缩放 → 收起键盘”路径：继续编辑且键盘仍打开时保留原布局；
  失焦或按缩放比例还原后的可视高度恢复时，释放旧键盘标记和尺寸覆盖，避免底部导航一直隐藏。
  同时覆盖收起键盘后输入框仍聚焦的情况。普通布局视口仍交给浏览器缩放。
- 清理现行模板不再使用的 hero-action、section-heading 旧样式及动效选择器；
  Swup 的重复时长声明由共享 Motion 统一控制。
- 保留仍被目录使用的遮罩、旧搜索模板回退和 Markdown 基础样式，不按名称猜测删除活跃代码。
- 增加 360px 文字间距覆盖、键盘/缩放边界回归及整体资源预算；所有检查只使用临时通用内容。

## 发布前人工验收

- [ ] 当前正式界面在 1440 / 390 / 360px 的明暗截图与 PR-00 / 已确认原型对照确认。
- [ ] 实际 iOS Safari 与 Android Chrome：输入法、键盘收起、双指缩放、旋转、安全区和触屏滚动。
- [ ] 桌面实际浏览器 200% 缩放、长文本与焦点不被浮层遮挡。
- [ ] VoiceOver 或对应读屏：导航名称、弹窗顺序、Esc、关闭与焦点返回。
- [ ] 代表性低性能设备：连续阅读/写作与面板交互、玻璃关闭/开启的滚动、发热和耗电。
- [ ] 部署后重新发布一次通用验证内容，检查公开页面与编辑器预览；生产内容由站点作者操作。

这些项未完成时，状态应为发布候选，不能宣称已完成真实 Safari、能耗或整站 AA 验收。

## 回滚

每阶段使用独立 PR 合并提交，可通过 GitHub Revert 对应 PR 并等待 Worker 构建。
若已重新发布过公开模板，回滚后再次发布网站信息，以旧代码重新生成公开页面。
若回滚多个阶段，按依赖从后向前操作，避免保留依赖已被移除的共享模块。
不删除 R2、不清空用户数据、不重建账号；UI 回滚不需要恢复存储备份。
PR-09 单独回滚只撤销收尾修复、检查与文档，不影响此前阶段的设计系统。
